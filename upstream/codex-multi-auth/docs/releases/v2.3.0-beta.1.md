# v2.3.0-beta.1

Fixes login reporting the wrong outcome, and `--manual` calling everything a cancellation.

```bash
npm i -g codex-multi-auth@beta
```

## Login said "Added account" when it hadn't

Signing in with the same email on a different workspace folded onto your existing saved entry — but the CLI printed `Added account` regardless.

The cause: the CLI had its own copies of the account-resolution and save logic, and those copies had drifted from the workspace-aware versions the runtime proxy uses. They never persisted workspaces and always reported an insert.

Login now tells you what actually happened — **`Added account`**, **`Updated existing account`**, or **`Rebound workspace for existing account`** — based on what the write really did.

Workspaces are now saved too, so `codex-multi-auth workspace <account>` works after a same-email multi-workspace login. Per-workspace enabled/disabled state survives re-logins, and `login --org <id>` tracks workspaces as well (it used to return before workspace discovery ran).

A first workspace-aware re-login of an older account counts as `Updated existing account`, not `Rebound workspace` — quiet enrichment isn't a rebind.

## `--manual` reported every failure as "Cancelled"

The manual callback reader returned nothing for a genuine cancel, a callback URL missing its parameters, *and* an OAuth state mismatch — and the caller treated all three the same way. So pasting a malformed URL just told you "Cancelled", which is both wrong and unhelpful.

Those are now distinguished. A malformed URL and a state mismatch each exit non-zero with a specific message; a real cancellation behaves as before.

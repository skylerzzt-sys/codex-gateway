# v2.1.8

Makes `switch` actually stick, including in the Codex Desktop app.

```bash
npm i -g codex-multi-auth
```

## Pinning an account

`switch <index>` now writes a real pin that the rotation proxy honours ahead of session affinity, health scoring, and pool fallback. New `unpin` command clears it:

```bash
codex-multi-auth switch 2     # pin to account 2
codex-multi-auth unpin        # back to normal rotation
codex-multi-auth status       # shows the pin, warns if the runtime disagrees
```

`best` clears the pin as well.

If your pinned account is unavailable, you now get an explicit `503` with `codex_pinned_account_unavailable` rather than silently being served by a different account.

## Desktop app fixes

**`switch` didn't affect the Desktop app.** It now does.

**Session affinity locked the Desktop app to one account for 20 minutes.** Pinning, unpinning, or running `best` now clears affinity immediately — including for the request already in flight.

## Persistence fixes

- **Routine background saves wiped your pin.** The snapshot builder dropped the pin and affinity counter; it now refreshes them from disk before writing.
- Concurrent affinity bumps across processes are now atomic, so two CLI processes can't clobber each other.
- `unpin` retries through transient Windows file locks rather than silently losing your intent.
- Fixed pin leakage between proxy instances — the storage cache was shared rather than keyed per file path.
- `status` no longer prints `Pinned: account NaN` for a corrupt pin; it shows the raw stored value and points you at `unpin`.

# v2.1.7

Follow-up to v2.1.6 — the `preuninstall` hook it added never actually fires.

```bash
npm i -g codex-multi-auth
```

## The uninstall hook doesn't work

v2.1.6 wired `uninstall` cleanup to npm's `preuninstall` lifecycle script. `npm@7+` doesn't run that hook, so it was dead weight. It's removed.

**To uninstall fully, run both:**

```bash
codex-multi-auth uninstall
npm uninstall -g codex-multi-auth
```

The first reverses what postinstall did — unbinds app rotation, removes launchers, strips the plugin entry from `Codex.json`, clears the module cache, and removes a shared `bun.lock` only when no other Codex plugins are left.

## Other fixes

- `--dry-run` computes the `bun.lock` decision from your real plugin list instead of reporting "uncertain".
- `--clear-accounts` warns and exits non-zero when nothing is wired to handle it, rather than quietly doing nothing.
- Accounts with no account id no longer collapse into one another during email hydration, so a refreshed token lands on the right row.
- Restoring a missing `model_provider` or response-storage key now splices it in *before* the first section header. Appending it produced invalid TOML that Codex refuses to parse.
- Transient Windows file locks during `fix`, health checks, and quota-cache saves are now a partial-success warning rather than a hard failure.
- App-bind won't rewrite `config.toml` to point at a dead router — it now requires a running state and a live process.

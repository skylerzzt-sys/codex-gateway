# v2.1.9

Fixes `login --device-auth` quitting before you could finish signing in.

```bash
npm i -g codex-multi-auth
```

## What was wrong

`codex-multi-auth login --device-auth` exited with `Detected unsettled top-level await` while you were still authorising in the browser.

The polling timer was marked as not keeping the process alive — correct for background use, fatal for a foreground command, because Node just exited. The CLI now opts into keeping the loop alive until polling finishes or you cancel.

## Explicit login flags actually work now

`--device-auth`, `--manual`, and `--no-browser` were silently ignored if you already had accounts saved — the Accounts Dashboard menu intercepted `login` first, and your flag never got a look in.

Three related dead ends are fixed too. After an explicit-mode sign-in, declining "Add another account?" now exits, cancelling with Ctrl-C now exits, and hitting the 20-account cap now exits after telling you. All three previously dumped you back into a fresh sign-in prompt with no way out except killing the process.

## For library users

`DeviceAuthFlowOptions` gains an optional `keepAlive` flag. Background callers keep the old behaviour by default; foreground callers pass `keepAlive: true`. Cancellation clears the timer either way.

# v2.8.4

Fixes `codex app-server`, which didn't work at all with account rotation on. Rotation is on by default, so for most people it just didn't work.

```bash
npm i -g codex-multi-auth
```

## What was wrong

If your machine had ever run an app-server, it refused to start:

```console
$ codex-multi-auth-codex app-server --listen unix:///path/to/a.sock
Error: socket directory path exists and is not a directory:
  .../runtime-shadow-homes/codex-multi-auth-runtime-home-XXXXXX/app-server-control
```

And if it did start, every client attached to a frozen snapshot of your thread list. Threads it created were written to a copy and thrown away on exit.

Both came from the same thing: rotation ran the server against a mirrored copy of your Codex home instead of the real one.

## What's fixed

`app-server` now uses your real Codex home, like the interactive TUI (since v2.8.0) and `resume`/`fork` (since v2.8.1). Rotation still applies — it travels as command-line overrides, so your `config.toml` is never touched.

Three rotation-helper fixes came with it:

- A short-lived server no longer leaves a helper process running for 12 hours after it exits.
- `app-server` no longer installs the CLI shim it didn't need. That shim was quietly setting `CODEX_MULTI_AUTH_RUNTIME_ROTATION_PROXY=0` on everything the server spawned, so nested commands ran unrotated and billed whatever account the official CLI picked. On Windows it also stops copying the ~100 MB Node binary on every launch.
- A helper that can't start now exits with a one-line error instead of an unhandled-rejection stack trace.

That last one fails hard on purpose. A server that silently loses rotation bills the wrong account and you'd never see it; a server that fails to start is a problem you notice.

## Check it worked

```bash
codex-multi-auth-codex app-server --listen unix:///tmp/codex-app-server.sock
```

It should start, and clients should see your existing threads.

One gotcha that isn't ours: Codex rejects a socket path whose parent is a symlink, so `--listen unix:///tmp/x.sock` fails on macOS because `/tmp` links to `/private/tmp`. Use a real path.

If you'd been setting `CODEX_MULTI_AUTH_RUNTIME_ROTATION_PROXY=0` to get app-server working, drop it — that bought you a working server by turning rotation off:

```bash
unset CODEX_MULTI_AUTH_RUNTIME_ROTATION_PROXY
codex-multi-auth rotation status
```

## Worth knowing

- `app-server` no longer creates a shadow home or shim directory. It reads and writes your real home, which is what makes threads persist.
- Its rotation helper stops when the server exits, rather than idling out. This is the opposite of the interactive TUI, and it's deliberate.

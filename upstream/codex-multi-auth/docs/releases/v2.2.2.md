# v2.2.2

Fixes `forecast` reporting working accounts as unavailable.

```bash
npm i -g codex-multi-auth
```

## What was wrong

When rotation skips an account, it records why. Some of those reasons expire on their own — a rate-limit window, a cooldown — but `token-exhausted` has no clock on it. Nothing ever cleared it, so the reason sat there indefinitely and `forecast --live` kept reporting a perfectly working account as unavailable.

## What's fixed

A successful request now clears the account's recorded skip reason. That's the real fix — the state gets cleaned up at the source.

`forecast` also stopped trusting stale time-bounded reasons. It now cross-checks against disk: `rate-limited` is ignored when there's no active reset window, and `cooling-down` is ignored when the cooldown is absent or already elapsed.

Reasons without a natural expiry — `circuit-open`, `token-exhausted`, `policy-blocked` — are still applied as written, since those are now cleared properly on success.

`doctor`'s `forecast-runtime-alignment` check shares the same evaluation, so it stopped raising a spurious warning for this too.

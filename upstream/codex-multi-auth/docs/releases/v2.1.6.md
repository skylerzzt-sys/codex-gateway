# v2.1.6

Adds an `uninstall` command that actually cleans up.

```bash
npm i -g codex-multi-auth
```

> **Note:** this release wired cleanup to npm's `preuninstall` hook, which doesn't fire on `npm@7+`. See [v2.1.7](v2.1.7.md) — run `codex-multi-auth uninstall` explicitly before `npm uninstall`.

## `uninstall`

```bash
codex-multi-auth uninstall [--dry-run] [--json] [--clear-accounts]
```

Reverses what postinstall did: unbinds Codex app rotation, removes OS launchers, strips the plugin entry from `Codex.json`, clears the module cache, and removes a shared `bun.lock` only when no other Codex plugins remain.

## Fixes

- Accounts with no account id no longer collapse into one another during email hydration, so a refreshed token lands on the right row.
- Restoring a missing `model_provider` or response-storage key now splices it in *before* the first section header. Appending it produced invalid TOML that Codex won't parse.
- Transient Windows file locks during `fix`, health checks, and quota-cache saves are a partial-success warning rather than a hard failure.
- App-bind no longer rewrites `config.toml` to a dead router's port — it now requires a running state and a live process.
- A stream-failover fix so the chunk that ends a stall isn't dropped.
- `withStorageLock` can no longer leave the storage mutex held if setup throws.

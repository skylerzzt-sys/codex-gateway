# v2.8.0

Stops macOS asking for your login keychain password over and over, and stops interactive sessions reindexing your history on every launch.

```bash
npm i -g codex-multi-auth
```

This is a minor release rather than a patch because it changes behaviour: the wrapper now writes `cli_auth_credentials_store` into `~/.codex/config.toml` on first run and on startup, where before it only did so during a login, switch, or repair. There's an opt-out below.

## The keychain prompts

CodexBar — or any front-end that runs the official `codex` binary directly — kept triggering the keychain prompt, and "Always Allow" never made it stick.

None of our own storage touches the keychain; it's plain JSON. The prompts come from the **official** CLI reading `cli_auth_credentials_store` from `~/.codex/config.toml`. When that says `"keychain"`, it reaches into the keychain on every launch.

We were already passing `-c cli_auth_credentials_store="file"` to everything *we* launched — but a menu-bar app running the official binary reads the config file instead. And we only wrote that setting during a login or switch, so you could install the package, drive Codex through a third-party front-end, and sit on the keychain store forever.

It's now written on first run and re-checked on startup, which also repairs a config that something else flipped back — a fresh official `codex login`, say.

Only the top-level setting is touched. Anything inside a `[profiles.*]` table is left exactly as you wrote it, line endings are preserved, and `'file'` in single quotes counts as already correct.

**Nothing reads or deletes your keychain items** — doing that would raise the very prompt this fixes. Old credentials stay where they are, are simply no longer read, and you can clear them by hand in Keychain Access.

`doctor --fix` can now repair this directly too, and reports it correctly even on a machine with no accounts registered yet — which is exactly the state you're in when you hit this.

## Session history reindexing

Interactive sessions used to copy your Codex home to a temporary directory, run there, and sync back on exit. That made the official CLI reindex your session history on every launch, and put a copy-and-sync step in the path of your real state.

They now run against your real Codex home and get rotation through command-line overrides instead. Nothing to reindex, nothing to sync back, and your `config.toml` is never rewritten with a rotation provider.

Two sessions can now run at once against the same state — same as running the official CLI twice. Nothing copies or syncs on this path, so there's nothing to clobber.

Non-interactive commands, `codex app`, and `app-server` are unchanged.

## Upgrade notes

Nothing to do. The first run after upgrading reconciles your config for you.

If you were already installed, only the new credential-store step is replayed — app bind and launcher install are deliberately *not* rerun, so shortcuts you removed stay removed.

Two opt-outs, both in [docs/configuration.md](../configuration.md):

| Variable | Effect |
| --- | --- |
| `CODEX_MULTI_AUTH_ENFORCE_CLI_FILE_AUTH_STORE=0` | Never write `cli_auth_credentials_store` into `config.toml` |
| `CODEX_MULTI_AUTH_FORCE_FILE_AUTH_STORE=0` | Also stop passing it to sessions the wrapper launches |

Set the **first** to keep your `config.toml` untouched — that's the file front-ends like CodexBar read, so it's the one that restores keychain behaviour for them. Set **both** if you want the keychain everywhere.

# v2.6.1

Fixes OAuth login on WSL.

```bash
npm i -g codex-multi-auth
```

If you had `codex-multi-auth` installed on a Windows host *and* inside WSL, sign-in broke in both. Removing the Windows install was the only thing that made WSL work.

Everything here is gated behind a WSL check that's `false` everywhere else, so native Windows, macOS, and Linux are untouched.

## What was wrong

**No browser ever opened.** WSL reports itself as Linux, so the launcher tried `xdg-open` — which isn't installed on a stock WSL Debian. It failed silently and login just looked like a hang. WSL now opens the *Windows* browser via `wslview`, falling back to PowerShell interop, then the Linux opener.

**The clipboard copied to the wrong side.** Manual paste is exactly where WSL users ended up, and the URL was going to the distro's clipboard instead of the Windows one they paste from. It now routes through `clip.exe` first.

**A lost callback now explains itself.** The OAuth redirect is registered as `http://localhost:1455/auth/callback`, so the port is fixed and can't be renegotiated. A browser launched from WSL runs on Windows, and Windows resolves `localhost:1455` against its own loopback first — so a Windows-side login holding that port receives the redirect your WSL listener is waiting for. From inside the distro this is invisible: the listener binds fine and simply never hears anything.

`login` now names that conflict, shows how to find the listener on each side, and points you at `login --device-auth`, which needs no callback port.

We only *assert* a port conflict when we actually observe one (`EADDRINUSE`). A callback that never arrives is far more often a cancelled sign-in, so that case leads with "if you closed the browser, just run login again" and offers the conflict explanation as a maybe.

## Docs

- New [Windows and WSL side by side](../troubleshooting.md#windows-and-wsl-side-by-side) section.
- Documented that Windows and WSL keep **separate state directories** — accounts aren't shared, and you have to sign in to each independently.

## Known rough edge

A WSL login that loses the callback still waits out the full five-minute poll before printing the guidance. Showing the hint earlier while continuing to wait is a follow-up.

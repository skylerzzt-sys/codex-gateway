# v2.3.0

Fixes a permanent `503` that could wedge rotation even with healthy accounts.

```bash
npm i -g codex-multi-auth
```

Promotes the `2.3.0-beta` line to stable — everything from beta.1 through beta.3 is included.

## The deadlock

You'd get this forever, while `doctor` reported everything fine:

```
503 All managed Codex accounts are temporarily unavailable for this runtime request.
```

Per-account transient state — cooldowns, rate-limit windows — is saved to disk. So when the recovery routine reloaded from disk to clear a wedged pool, it restored exactly the state that had wedged it. And the recovery guard refused to run at all whenever any account was marked rate-limited or cooling down, which is precisely the situation it existed to fix.

Both halves are fixed: recovery is now only suppressed for `policy-blocked` (which is external and won't change on a reload), and the reload clears transient state and flushes it before publishing, so the cleared state survives a restart.

## Two more durability gaps

Both are the same class of bug — code that changes account state but forgets to schedule the write:

- The missing-`accountId` cooldown branch set a cooldown but never saved it, so a restart within 30 seconds dropped it and immediately re-selected the broken account.
- The short-retry `429` path set a rate-limit window, then slept and retried without saving. A crash during that sleep lost the window.

Every mutation site was audited; these were the gaps.

## Escape hatch

`codex-multi-auth rotation reset-rate-limits` is still there if you need to clear things manually.

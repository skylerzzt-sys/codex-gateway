# v2.8.1

Fixes `mcodex resume` hanging on a blank screen, the shell prompt sometimes not coming back, and four security advisories.

```bash
npm i -g codex-multi-auth
```

## What was wrong

`mcodex resume <session-id>` printed its status line and then sat on an empty screen forever. Plain `codex resume` worked fine, which made it look like our bug — and it was.

v2.8.0 moved interactive sessions onto your real Codex home, but it only recognised "interactive" as *a command with no subcommand*. `resume` and `fork` are interactive too, they just carry a subcommand, so they kept using a temporary copy of your home.

That copy deliberately leaves out the session database. The reporter's numbers say it plainly: their real database held 257 threads including the one they asked for; the two temporary ones created by the failed launches held 126 and 128, and neither contained it. The screen was blank because the session genuinely wasn't there.

`resume` and `fork` now use your real Codex home, same as a plain interactive session. Rotation still applies.

## Also fixed

**The shell prompt didn't always come back.** After an interrupted or failed Codex exit, the wrapper could print Codex's goodbye message and then hang — `Ctrl+Z` showed it parked as a stopped job. Shutdown now escalates to a hard kill after the grace window and tears down the helper's pipes, which is the part that actually frees things on Windows.

**`--help` no longer starts a rotation proxy.** `resume --help` and friends print help and make no model requests, but they were still paying for the full rotation setup — and leaving a background helper running afterward. Help now forwards straight to the official CLI.

## Security

| Package | From | To | Fixes |
| --- | --- | --- | --- |
| `hono` | 4.12.21 | 4.12.33 | JSX context leaking between requests; XSS via the `cx()` escaping bypass |
| `undici` | 6.25.0 | 6.28.0 | Set-Cookie injection; WebSocket fragment DoS; keep-alive queue poisoning; SameSite downgrade |

`undici` stays on 6.x deliberately — it's our only runtime HTTP dependency and it sets our Node 18.17 floor. Moving to 7.x would require Node 20. Two dev-only advisories are pinned through `overrides`.

## Check it worked

```bash
mcodex resume <session-id>
```

Should open the resumed session, and `/exit` should give you your prompt back.

If you'd been setting `CODEX_MULTI_AUTH_RUNTIME_ROTATION_PROXY=0` to work around this, drop it — that fixed resume by turning rotation off:

```bash
unset CODEX_MULTI_AUTH_RUNTIME_ROTATION_PROXY
codex-multi-auth rotation status
```

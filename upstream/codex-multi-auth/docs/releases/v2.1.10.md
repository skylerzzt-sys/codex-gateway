# v2.1.10

Stops a long-running proxy staying wedged after your accounts have recovered.

```bash
npm i -g codex-multi-auth
```

## What was wrong

When the pool ran out of usable accounts, in-memory circuit breakers stayed open even after the state on disk had recovered. A long-lived proxy could sit there refusing requests for accounts that were fine again.

It now resets its volatile trackers, reloads accounts from disk once, and retries selection — so recovery on disk actually reaches a running proxy.

Pinned accounts are unaffected: an unavailable pinned account still fails explicitly rather than quietly rotating to a different one.

## Diagnostics

- **Pool-exhausted `503`s now tell you why each account was skipped**, with a targeted recovery hint.
- `report` and `doctor` factor in cached quota state when judging readiness, so an account whose quota is exhausted can't be reported as ready.
- `rotation reset-runtime --json` no longer wipes diagnostics when the app-bind restart fails — that's exactly the evidence you need to work out what went wrong.

## Packaging

The npm package now ships only runtime and install scripts, dropping internal benchmark, audit, and maintenance ones.

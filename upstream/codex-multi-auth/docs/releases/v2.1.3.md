# v2.1.3

Repairs a corrupted session index.

```bash
npm i -g codex-multi-auth
```

Wrapper-launched sessions now repair `session_index.jsonl` when a known thread-store write leaves it damaged. The repair only runs with real session metadata as evidence, and concurrent repairs are serialised so two sessions can't fight over the same file.

Also: app-bind status warnings now resolve the active status path before printing their history-visibility and model-speed guidance, so the advice matches your actual setup.

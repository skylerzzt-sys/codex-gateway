# v2.8.5

Bug fixes for background rotation helpers. Nothing to migrate — install and go.

```bash
npm i -g codex-multi-auth
```

## What was wrong

Background helper processes never shut down. One user ended up with 183 of them eating 5.58 GB, the oldest 33 hours past a timeout that should have killed it in 12. Their machine was swapping.

Three things caused it:

- **Helpers couldn't tell if their launcher was still alive.** They checked "does anything hold this process ID", and the OS reuses IDs. Any unrelated process landing on that number reset the helper's 12-hour clock — forever.
- **Nothing else ever stopped them.** That clock was the only exit.
- **They all wrote to the same status file**, so `rotation status` showed a random helper, and helper metadata piled up (701 leftover files on one machine).

## What's fixed

- Helpers now identify their launcher by process ID **and** start time, so a reused ID no longer looks like a live launcher.
- A hard 24-hour ceiling stops any helper regardless of what the activity tracking thinks.
- Each helper writes its own status file, and leftovers get cleaned up on the next launch.
- `rotation status` reports one consistent answer. It previously could name one helper on the status line and mark a different helper's account as current, in the same command.

## If you're already affected

Check, then clean up:

```bash
ps ax | grep -c 'codex-multi-auth-runtime-app-helper'
codex-multi-auth rotation unbind-app
```

`unbind-app` stops every helper it can confirm is yours and clears their files. Anything it can't verify is left alone with a warning.

## Also in this release

- Removed the deprecated `@openauthjs/openauth` dependency. PKCE is now generated directly from `node:crypto` (RFC 7636).
- Test-only failure hooks in the published wrapper now need an explicit opt-in, so a stray environment variable can't switch one on.

## Two things to know

**Helper status files moved to one-per-process.** If you read `~/.codex/multi-auth/runtime-rotation-app-helper.json` directly, switch to `runtime-rotation-app-helper.<pid>.json`. The old path is still read, but nothing writes it anymore.

**Two new optional settings:**

| Variable | Default | What it does |
| --- | --- | --- |
| `CODEX_MULTI_AUTH_APP_ROTATION_MAX_LIFETIME_MS` | 24h | Hard cap on helper lifetime. `0` disables. |
| `CODEX_MULTI_AUTH_APP_ROTATION_DETACHED_IDLE_MS` | 15m | Shorter timeout for a helper whose launcher died and that never served a request. `0` keeps the old 12h behaviour. |

That second one is deliberately narrow: a `codex app` session sitting idle between messages holds no connection, so anything broader would have killed working sessions.

# v2.3.0-beta.0

Adds opt-in drain-first account scheduling.

```bash
npm i -g codex-multi-auth@beta
```

## What it does

By default, rotation spreads load across your pool. That means all your quota windows tend to fill up — and reset — together.

`sequential` mode drains one account fully before moving to the next:

```bash
CODEX_AUTH_SCHEDULING_STRATEGY=sequential
```

Every request stays on the current account until it's genuinely exhausted — rate-limited, cooling down, circuit-open, or disabled — then moves to the next usable one. When an earlier account's quota window recovers, it reclaims the slot on the next scan.

The effect is that your quota windows stagger over time instead of resetting in lockstep, which should mean longer uninterrupted sessions across a multi-account pool.

## What doesn't change

`hybrid` is still the default and behaves exactly as before — weighted health and freshness scoring, plus per-session affinity. If you don't set this, nothing changes.

A manual `switch <n>` pin still overrides scheduling in both modes.

One deliberate difference: in `sequential` mode, per-session affinity is bypassed. Every request follows the single active account rather than a per-chat sticky one — that's the point of draining.

## Why it's a beta

Whether drain-first actually gives you longer sessions depends on your pool's real quota-window timing, which is hard to predict. It ships as a beta so it can be validated against real accounts before a stable cut.
